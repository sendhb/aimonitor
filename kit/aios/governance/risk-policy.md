# Risk Policy — 操作风险分级

| 级别 | 定义 | 示例操作 | 审批 |
|------|------|---------|------|
| 🔴 P0 | 不可逆/高影响 | 数据库 schema 变更、支付逻辑修改、账号删除、权限变更、生产配置修改 | **必须人工批准** |
| 🟡 P1 | 可逆但需审查 | API 契约修改、共享类型定义变更、CI/CD 配置、新依赖引入 | **TASK 声明 + reviewer 审查** |
| 🟢 P2 | 常规开发 | 业务逻辑实现、UI 修改、文档更新、测试编写 | TASK 追踪即可 |
| ⚪ P3 | 低风险 | 注释/格式/命名修正、README 更新 | 自由执行 |

TASK 必须声明 `metadata.risk`。P0 任务在关闭前必须填写不可为空的 `metadata.approval-ref`，并关联人工批准记录；P1/P0 必须走独立 reviewer 审查。

## 风险升级

任一条件触发 → 自动升级一级：

1. 修改影响 > 5 个文件
2. 修改跨越 > 2 个模块
3. 涉及 > 1 种编程语言
4. 存在 `depends-on` 未解决的阻塞任务

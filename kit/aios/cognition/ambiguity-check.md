# Ambiguity Check — 歧义澄清

> 不明确的需求 = 注定返工的实现。在执行前把所有"不确定"变成"确定"（或明确假设）。

## 检查表

| 维度 | 检查项 |
|------|--------|
| 范围 | 是否明确了"做什么"和"不做什么"？ |
| 边界 | 输入非法时怎么办？空值？超大值？并发？ |
| 平台 | 是否需要跨平台？iOS/Android/Web/Desktop？ |
| 语言 | 是否需要国际化？默认语言？ |
| 性能 | 是否有延迟/吞吐要求？ |
| 兼容 | 是否需要兼容旧版本/旧数据？ |
| 权限 | 什么角色可以执行？未登录用户怎么办？ |
| 回滚 | 失败了怎么办？能回滚吗？ |

## 输出

```markdown
## Ambiguity Check
- [x] <已明确项 1>
- [x] <已明确项 2>
- [ ] <未明确项 1> — 默认假设：<×××>，请确认
- [ ] <未明确项 2> — 默认假设：<×××>，请确认
```

## 规则

- 每个 [ ] 未明确项必须有默认假设（AI 不应卡住）
- 默认假设写入 TASK 的"备注"段
- 高风险歧义（影响安全/数据）必须先确认再执行
